# Agent Note: 发布 1.0.16 + 修掉 build.sh 静默跳过签名的假绿

Status: implemented

## Problem

用户要求「直接发版本」，并确认升号到 1.0.16、出三端全平台产物。

构建过程中发现一个**假绿门禁**：

- `tools/build.sh` 的 Windows 签名段判据写成 `[ "$(uname -s)" = "MINGW64_NT"* ]`
- 在 POSIX `test`（`[ ]`）里 `*` 是**字面量**，不做通配展开，条件**恒为假**
- 后果：Windows 上签名步骤被**静默跳过**，日志里一个字都没有，
  构建显示「成功」，但产物是 `NotSigned`

这也解释了此前 `agent/dist/*.exe` 一直是 `NotSigned` 而没人发现的原因。

## Decision

### 1. 版本号 1.0.15 → 1.0.16（5 处源文件）

`app/src-tauri/tauri.conf.json`、`package.json`、`app/package.json`、
`app/src-tauri/Cargo.toml`、`agent/main.go` 的 `const Version`。

### 2. build.sh 签名门禁改为真的能跑

- 判据换成 `case "$OS_NAME" in MINGW*|MSYS*|CYGWIN*)`（`case` 的 pattern 才是通配语义）。
- 顺便修掉调用路径：脚本开头 `cd "$(dirname "$0")/.."` 已切到仓库根，
  此时再 `"$(dirname "$0")/sign-windows.ps1"` 会拼出 `tools/tools/...`。
  改用脚本开头算好的 `$ROOT`。
- `*` 分支与 `powershell.exe` 缺失分支都**显式打印原因**，不再静默。

修复验证方式是**门禁真的变红过**：改完判据后签名第一次真正执行，
立刻暴露出上面那个路径错误（`sign-windows.ps1 does not exist`，exit 127）。
这正是本次修复的价值 —— 之前这个错误永远不会被看见。

## Alternatives considered

- **继续用 `[ ]` 但写对**：`[ "${OS_NAME#MINGW}" != "$OS_NAME" ]` 之类也能work，
  但可读性差且容易再错。`case` 是 shell 里做前缀匹配的正规写法。放弃。
- **直接无条件调用签名脚本、由脚本自己判断平台**：会把「非 Windows 所以不签」
  变成「跑了但什么都没做」，更难判断。保持显式分支。放弃。
- **把签名失败降级为警告**：签名是消除「未知发布者」警告的唯一手段，
  失败必须让构建失败，否则又会回到「构建成功但产物没签」的状态。放弃。

## Consequences

收益：
- 1.0.16 的 Windows 产物**真的签上了**（`landeck.exe`、两个 agent exe、
  NSIS 安装包、uninstaller 均 `Valid`）。
- 签名步骤失败会让构建失败，不会再出现「构建绿灯但产物 NotSigned」。

代价与边界：
- 签名脚本在 Windows 平台会真实执行，证书未就绪时会**让构建失败**；
  此时需要先跑 `tools/sign-windows.ps1 -Setup`。这是有意的严格化。
- 非 Windows 平台会打印一行「跳过签名：当前平台 xxx 不是 Windows」，
  不是错误。

## Testing

- **门禁变红验证**：修好判据后签名首次执行即报错
  （`The argument 'tools/sign-windows.ps1' to the -File parameter does not exist`，exit 127），
  证明判据真的从「恒假」变成了「会执行」。
- 修好路径后 `build.sh` 全程 exit 0，日志出现 `== 签名 Windows 产物 ==`。
- 产物签名逐一验证：`Get-AuthenticodeSignature` → `Valid`，
  指纹与本地自签名证书一致（`<证书指纹>`），
  主体 `CN=LanDeck (本地自签名)`。
- 版本号嵌入二进制验证（运行而非 strings）：
  `landeck-agent-windows-amd64.exe --version` → `LanDeck Agent 1.0.16 (windows/amd64)`。
- APK：`aapt2 dump badging` → `versionName='1.0.16' versionCode='1000016'`；
  `apksigner verify` 证书 SHA-256 `bd3904c8...5642` 与既有 keystore 一致。
- 前端端到端（无头 Chrome 连 agent 内嵌前端，1.0.16 真实代码）：
  路由重定向 `/stats`、`/activity`、`/nonexistent` 均落到 `/devices`，
  正常路由不受影响；扫描期间 `worstFrame=19ms`、601 帧、**0 长任务**；
  头像 `/self/icon` 返回 `200 image/png 2392B`、`Cache-Control: no-cache`、
  带 `If-None-Match` 得 **304**；列表与详情页头像 URL 一致；
  头像图片真实解码（192×192）；抽屉动画为 `ldk-drawer-panel`（CSS）；
  抽屉 header `padding-top: 4px`；`/api/v1/stats` 与 `/api/v1/activity` 均 **404**。
