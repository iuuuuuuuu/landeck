# Agent Note: 文件与定时下沉到设备详情页；硬件卡片等高与滚动修复

Status: implemented

## Problem

用户提了两类问题：

1. **信息架构**：文件管理、定时任务作为一级导航项，但它们都是「针对某一台被控机」的操作，
   挂在顶级导航里既占了位置，又与「设备」页的语义重复。用户要求移进设备详情页。
2. **硬件卡片**：
   - 同一行卡片高度不一致（`items-start` 让行数少的卡片比同行矮），视觉参差；
   - 鼠标停在硬件区域时**整页都滚不动**。

## Decision

1. **下沉为详情页内的右侧抽屉**（`components/device/DetailDrawer.tsx`）：
   - 文件浏览是纵向长列表，需要全高；居中模态会被视口高度卡死，抽屉给
     `w-full sm:w-[min(720px,92vw)]` + 独立滚动。
   - 不新增路由 → 详情页始终挂载，实时订阅不断，关闭后滚动位置天然保留。
   - 抽屉 z-40，`ScheduleModal` 以 z-50 叠在其上，不需要额外层级处理。
   - ESC 关闭时会检测是否还有 `[aria-modal="true"]` 打开，避免把上层弹窗一起关掉。
   - `Files.tsx` / `Schedules.tsx` 抽出 `FilesPanel` / `SchedulesPanel`（保持原组件不动），
     原页面留薄壳；`/files`、`/schedules` 重定向到 `/devices`，旧书签不 404。
2. **硬件卡片等高**：去掉栅格上的 `items-start`（回到 stretch），Group 改
   `flex flex-col` + 内容区 `flex flex-1 flex-col justify-between` ——
   富余高度摊到行间距，而不是在底部堆一块空白。窄屏单列仍按内容高度。
3. **滚轮失效按两层根因修**：
   - 内层 `overflow-y:auto` 在内容压缩后（≈500px < 640px 上限）永远「有 scrollport 但没得滚」；
   - 叠加 `overscroll-contain` 掐断滚动链 → 内层不滚、也不冒泡给页面，表现为整页卡死。
   - 修法：去掉 `overscroll-contain` 改为 `overscroll-y-auto`（允许冒泡）、
     上限改 `max-h-[min(70vh,640px)]`（随视口收），并**刻意不加** `scrollbar-gutter: stable`
     —— 那正是「内容不足时预留一条空白」的来源。

## Alternatives considered

- **二级页面（新路由 `/devices/:id/files`）**：会多一层路由与返回逻辑，且离开详情页就断掉实时订阅，
  关回来还要恢复滚动位置。放弃。
- **居中模态**：文件列表需要高度，模态受视口限制且窄屏更挤。放弃。
- **弹层里再选一次设备**：用户正在看某台设备，再选一次是多余动作且容易选错。放弃。
- **硬件卡片保持 `items-start` 只调 padding**：参差感来自行高不齐，不调对齐方式治不了。放弃。
- **给内层加 `scrollbar-gutter` 让滚动条常驻**：会增加一条永久空白，与「压缩空白」的目标相反。放弃。

## Consequences

收益：导航从 8 项降到 6 项（本机/设备/发现/统计/活动/设置）；文件与定时在设备上下文里打开，
不用二次选设备；硬件区同行等高且窄屏不留空洞；滚轮在硬件区能正常滚、滚到底还能继续滚页面。

代价与边界：
- `Files.tsx` / `Schedules.tsx` 现在同时存在「面板」与「薄壳页」两种形态，
  旧的独立页面已不可达（路由重定向），保留薄壳只是为了少改一处将来可能复用的入口。
- 等高方案的理论上限：某行里「2 行卡」挨着「4 行卡」时，前者会把 36px 富余全摊到唯一一个行间距，
  看起来行距偏松。现有排序（同类相邻）已避开大多数情况，不是通用解法。
- 实测：14 个分组排 7 行、**同行高度差 0**；`scrollHeight 713 > clientHeight 630` 可滚。
- 移动端抽屉占满屏宽、内容区独立滚动的观感，需真机确认（本地只验了 390 宽的文本与溢出）。
